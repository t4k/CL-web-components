# CL-web-components

Standards-based Web Components used by Caltech Library across its sites and
projects. Each one is a custom HTML element that works without a framework,
encapsulates its own styles in a shadow root, and — where it makes sense —
falls back to plain HTML when JavaScript is unavailable.

**Documentation and live demos: <https://caltechlibrary.github.io/CL-web-components/>**

## Components

| Element | What it does |
| --- | --- |
| `<card-layout>` | A responsive three-card layout for featured content, configured by attributes. |
| `<footer-global>` | The standard Caltech Library footer, with full contact and site information. |
| `<footer-global-lite>` | A lighter-weight footer for pages that need less. |
| `<table-sortable>` | Wraps a table and makes it sortable by column heading, with a filter input. |
| `<textarea-agent-list>` | Wraps a textarea holding a list of agents expressed as JSON. |
| `<textarea-csv>` | Wraps a textarea holding CSV and presents it as an editable table. |
| `<ul-a-to-z-list>` | Turns a `<ul>` into an A-to-Z navigable list; the plain list remains as a fallback. |

## Quick start

Load every component at once and use the elements directly:

```html
<script type="module"
        src="https://caltechlibrary.github.io/CL-web-components/mod.js"></script>

<ul-a-to-z-list>
  <ul>
    <li><a href="#anteater">Anteater</a></li>
    <li><a href="#bison">Bison</a></li>
  </ul>
</ul-a-to-z-list>
```

Or load just the one you need:

```html
<script type="module"
        src="https://caltechlibrary.github.io/CL-web-components/src/table-sortable.js"></script>
```

To vendor the code instead of loading it from the web, download
`cl-web-components.js` from the
[latest release](https://github.com/caltechlibrary/CL-web-components/releases/latest)
and serve it yourself.

Each component's page in the documentation covers its attributes, slots, and
behavior in detail.

## What's in this repository

| Path | Contents |
| --- | --- |
| `src/` | Component source. One file per component, plus shared helpers. |
| `mod.js` | Entry point. Re-exports every component; importing it registers them all. |
| `docs/` | Documentation sources and demo pages. Built into the website. |
| `pandoc/` | Template and Lua filters used to render the website. |
| `css/` | Stylesheets published alongside the components. |
| `test/` | Tests, run with `deno test`. |
| `tools/` | Build helpers. `version.js` writes `src/version.js` from `codemeta.json`. |
| `codemeta.json` | Project metadata. `CITATION.cff` and `src/version.js` are generated from it. |
| `.github/workflows/` | Build, docs deployment, release, and CDN publishing. |

Assets generated by the build workflows are ignored.

## Contributing

You need [Deno](https://deno.com/) 2.7 or later. Nothing else.

```sh
git clone https://github.com/caltechlibrary/CL-web-components.git
cd CL-web-components
deno task build
```

That writes `src/version.js` and then the bundles into `dist/`; both are
ignored. To try a change, edit the component in `src/`, rebuild, and open the
matching demo page in `docs/` — for example `docs/demo_table-sortable.html`.

Run the tests with:

```sh
deno test --allow-read
```

Be aware that `test/textarea-csv_test.js` does not currently run: it imports
`parseCSV`, which moved to `deprecated/` during an earlier reorganisation, from
a path that no longer resolves. Whether to point it at `deprecated/`, drop
those cases, or bring `parseCSV` back is an open question.

A few conventions worth knowing before you open a pull request:

- **`CITATION.cff` is generated.** It is derived from `codemeta.json` and
  rewritten by CI on every push to `main`. It is in the repository so GitHub
  can read it, but editing it directly does nothing lasting — your changes are
  overwritten on the next run. Change `codemeta.json` instead.
- **`src/version.js` is generated too, and ignored.** `deno task build` writes
  it from `codemeta.json` before bundling, so it appears in your working tree
  after a build but is never committed.
- **Everything else is hand-written**, including this README and all of
  `docs/`. Nothing generates them, so your prose will not be overwritten.
- Component naming follows
  [our conventions](https://caltechlibrary.github.io/CL-web-components/web_component_naming.html).

Bug reports and questions belong in
[Issues](https://github.com/caltechlibrary/CL-web-components/issues).
